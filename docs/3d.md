# HOOK 3D

HOOK now includes a dependency-free 3D scene and CPU renderer, with optional GPU/compatibility backends.

## API

```python
from hook import Engine3D, Vec3D, Transform

engine = Engine3D(800, 600)
cube = engine.add_cube("player", 2.0, Vec3D(0, 0, 4))
cube.transform.rotation = Vec3D(20, 30, 0)
engine.save_frame("frame.ppm")
```

The 3D foundation includes vectors, transforms, perspective cameras, meshes, materials, lights, scene objects, depth-buffer triangle rasterization and basic Lambert lighting.

## Android / Winlator-style direction

The renderer is deliberately separated from the scene API. On Android, HOOK can use the same compatibility philosophy as Winlator: keep HOOK's high-level scene representation independent from the host execution backend, then detect optional native graphics/compatibility components instead of pretending a GPU API is available.

The CPU renderer is always the fallback. `GPU3DBackend` reports detected graphics tooling, but does not claim to render through it yet. A future Vulkan/OpenGL backend can therefore plug into `Engine3D` without changing HOOK game code.

## Current scope

- 3D vectors and arithmetic
- Euler transforms: translation, rotation and scale
- Perspective projection
- Meshes and cubes
- Materials and colors
- Point-light Lambert shading
- Back-face culling
- Depth buffering
- PPM frame output
- GPU capability detection
- Android/compatibility-friendly backend boundary

This is a real software 3D renderer, not a placeholder, but it is not yet a production Vulkan/OpenGL game engine.
